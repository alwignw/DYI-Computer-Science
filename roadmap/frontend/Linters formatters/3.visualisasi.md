### Analogi Kehidupan Nyata: Penerbitan Buku/Majalah

Bayangkan Anda sedang menulis sebuah majalah teknis. Di dalam tim redaksi, Anda memiliki dua rekan kerja dengan spesialisasi yang sangat berbeda:

```text
┌────────────────────────────────────────────────────────────────────────┐
│                          DRAFT NULISAN ANDA                            │
│  "const user = "budi"  ;  if(user== "budi"){ console.log( 'Halo' )} " │
└────────────────────────────────────────────────────────────────────────┘
                                    │
                  ┌─────────────────┴─────────────────┐
                  ▼                                   ▼
       [ FORMATTER = Desainer Layout ]     [ LINTER = Proofreader / Editor ]
       • Mengatur margin & spasi.         • Cek tata bahasa & logika.
       • Memastikan font seragam.          • "Penggunaan '==' berisiko type
       • Merapikan baris & tanda baca.       coercion, gunakan '==='."
       • TIDAK PEDULI isi tulisan          • "Ada variabel yang di-import
         benar atau salah.                   tapi tidak pernah dipakai!"

```

1. **Formatter (Desainer Layout / Typesetter):**
* **Tugasnya:** Memastikan tulisan terlihat indah, memiliki margin yang pas, spasi paragraf konsisten, dan pemisahan baris tidak terpotong sembarangan.
* **Sifatnya:** Memperbaiki secara otomatis tanpa mengubah makna dari kalimat.


2. **Linter (Proofreader & Pemeriksa Fakta):**
* **Tugasnya:** Memeriksa apakah ada kalimat yang kontradiktif, klausa mati, fakta yang salah, atau kata yang berpotensi membingungkan pembaca.
* **Sifatnya:** Memberikan peringatan (*warning/error*) dan menyuruh Anda memperbaiki logika tersebut (meski sebagian bisa di-*auto-fix*).

### Visualisasi Transformasi AST

Bagaimana Linter dan Formatter melihat kode Anda secara internal melalui **Abstract Syntax Tree (AST)**:

#### Kode Asli (Teks Biasa)

```javascript
const x = 5;

```

#### Struktur AST (Bagaimana Mesin Melihat Kode Anda)

```text
VariableDeclaration (const)
 └── Declarator
      ├── Identifier (name: "x")
      └── Literal (value: 5)

```

#### Bagaimana Linter & Formatter Mengintervensi AST:

```text
                                [ TEKS KODE ]
                                      │
                                      ▼
                                [ AST NODE ]
                                      │
           ┌──────────────────────────┴──────────────────────────┐
           ▼                                                     ▼
 [ LINTER INSPEKSI ]                                   [ FORMATTER TRANSFORM ]
 "Lihat Node: VariableDeclaration"                    "Lihat Node: VariableDeclaration"
   │                                                     │
   ├─ Cek 1: Apakah 'x' dipanggil di Node lain?         ├─ Atur spasi sekitar '='
   │         --> TIDAK! (Raise: no-unused-vars)          ├─ Pastikan titik koma (;) ada di akhir
   │                                                     └─ Cetak ulang teks dari AST
   └─ Cek 2: Apakah 'x' di-reassign nanti?
             --> TIDAK. (Penggunaan 'const' BENAR)

```
