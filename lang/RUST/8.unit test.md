Rust memiliki dukungan bawaan yang luar biasa untuk **Unit Testing** (pengujian unit). Anda tidak perlu menginstal pustaka atau *framework* tambahan seperti di bahasa pemrograman lain. Semuanya sudah disediakan oleh pustaka standar Rust dan dikelola secara otomatis oleh **Cargo**.

Tujuan dari unit tes adalah menguji bagian terkecil dari kode Anda—biasanya satu fungsi tertentu—secara terisolasi, untuk memastikan fungsi tersebut berjalan sesuai ekspektasi.

---

## 1. Anatomi Dasar Unit Tes di Rust

Sebuah fungsi pengujian di Rust pada dasarnya adalah fungsi biasa yang diberi atribut khusus, yaitu `#[test]`.

Berikut adalah contoh paling sederhana:

```rust
fn tambah(a: i32, b: i32) -> i32 {
    a + b
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_tambah_sukses() {
        assert_eq!(tambah(2, 3), 5);
    }
}

```

Mari kita bedah komponen di atas:

* **`#[cfg(test)]`**: Atribut ini memberi tahu Rust untuk hanya mengompilasi modul ini saat Anda menjalankan perintah pengujian (`cargo test`). Kode tes tidak akan ikut dimasukkan ke dalam file distribusi produksi (`cargo build --release`), sehingga ukuran aplikasi Anda tetap kecil.
* **`mod tests`**: Komunitas Rust memiliki konvensi untuk membungkus semua unit tes ke dalam sebuah modul bernama `tests` di bagian bawah file kode sumber yang sama.
* **`use super::*;`**: Karena kode tes berada di dalam sub-modul (`mod tests`), baris ini berfungsi untuk menarik semua fungsi yang ada di modul utama (luar) agar bisa diuji di dalam modul tes.
* **`#[test]`**: Atribut wajib yang menandakan bahwa fungsi di bawahnya adalah sebuah fungsi pengujian yang harus dijalankan oleh Cargo.

---

## 2. Macro Pengujian yang Sering Digunakan

Rust menyediakan beberapa *macro* bawaan untuk memeriksa hasil dari kode Anda:

* **`assert!(kondisi)`**: Memastikan bahwa `kondisi` bernilai `true`. Jika `false`, tes akan gagal.
* **`assert_eq!(kiri, kanan)`**: Memastikan bahwa nilai `kiri` **sama dengan** nilai `right`. Sangat sering digunakan untuk mengecek output fungsi.
* **`assert_ne!(kiri, kanan)`**: Memastikan bahwa nilai `kiri` **tidak sama dengan** nilai `right`.

> **Tips:** Anda bisa menambahkan pesan kustom di dalam macro tersebut jika tes gagal, contoh:
> `assert_eq!(tambah(2, 2), 4, "Harusnya hasil dari 2 + 2 adalah 4");`

---

## 3. Menangani Kasus Khusus (Error & Panic)

### Menguji Kode yang Harusnya Error (`#[should_panic]`)

Terkadang, Anda ingin memastikan bahwa kode Anda *crash* atau *panic* ketika menerima input yang salah. Anda bisa menambahkan atribut `#[should_panic]`.

```rust
fn bagi(pembilang: i32, penyebut: i32) -> i32 {
    if penyebut == 0 {
        panic!("Tidak bisa membagi dengan nol!");
    }
    pembilang / penyebut
}

#[test]
#[should_panic(expected = "Tidak bisa membagi dengan nol!")]
fn test_bagi_nol_harus_panic() {
    bagi(10, 0);
}

```

*Tes di atas akan dinyatakan **LULUS** jika kode di dalamnya memicu `panic` dengan pesan yang sesuai.*

---

## 4. Cara Menjalankan Tes dengan Cargo

Untuk menjalankan pengujian, Anda cukup membuka terminal di folder proyek Anda dan mengetik:

```bash
cargo test

```

Cargo akan otomatis mengompilasi kode Anda, mencari semua atribut `#[test]`, menjalankannya, dan memberikan laporan yang sangat rapi.

### Trik Perintah `cargo test` yang Berguna:

* **Menjalankan Tes Spesifik:** Jika Anda hanya ingin menjalankan satu tes tertentu, cukup sebutkan namanya: `cargo test test_tambah_sukses`.
* **Filter Berdasarkan Nama:** Jika Anda punya banyak tes seperti `test_web_a`, `test_web_b`, Anda bisa menjalankan semuanya dengan `cargo test test_web`.
* **Melihat Output `println!`:** Secara default, Rust akan menyembunyikan hasil `println!` jika tes tersebut lulus. Jika Anda ingin memaksa output keluar, gunakan: `cargo test -- --nocapture`.

---

## Perbedaan Unit Test vs Integration Test di Rust

Rust membedakan tempat penulisan tes berdasarkan jenisnya:

1. **Unit Test:** Ditulis di **file yang sama** dengan kode sumbernya (seperti contoh di atas). Fokus menguji fungsi internal dan privat.
2. **Integration Test:** Ditulis di **folder terpisah bernama `tests/**` di luar folder `src/`. Fokus menguji aplikasi Anda dari luar, seolah-olah Anda adalah pengguna pustaka tersebut (hanya bisa mengakses fungsi publik).

Apakah Anda ingin mencoba membuat sebuah fungsi kecil dan menulis unit tesnya bersama-sama untuk melihat bagaimana Cargo menampilkan hasilnya jika tes tersebut gagal?
