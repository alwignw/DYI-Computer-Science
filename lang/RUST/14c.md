# UTF-8 vs UTF-16

## Ide dasarnya

Unicode hanya memberi **nomor** ke tiap karakter (misalnya `'A'` = 65, `'😀'` = 128512). Tapi komputer perlu **menyimpan nomor itu sebagai byte**. Cara menyimpannya disebut **encoding**. UTF-8 dan UTF-16 adalah dua cara berbeda untuk melakukannya.

Perbedaan utamanya ada di **satuan dasar** (code unit) yang dipakai:

| | UTF-8 | UTF-16 |
|---|---|---|
| Satuan dasar | 8 bit (1 byte) | 16 bit (2 byte) |
| Panjang per karakter | 1 sampai 4 byte | 2 atau 4 byte |

## UTF-8

Karakter yang nomornya kecil memakai byte sedikit, yang besar memakai byte lebih banyak:

| Rentang | Byte | Contoh |
|---|---|---|
| `U+0000` – `U+007F` | 1 | `A` |
| `U+0080` – `U+07FF` | 2 | `é` |
| `U+0800` – `U+FFFF` | 3 | `日` |
| `U+10000` – `U+10FFFF` | 4 | `😀` |

Ini cocok dengan yang sudah kita lihat sebelumnya:

```rust
println!("{}", 'a'.len_utf8());  // 1
println!("{}", 'é'.len_utf8());  // 2
println!("{}", '日'.len_utf8()); // 3
println!("{}", '😀'.len_utf8()); // 4
```

**Keunggulan:**
- Teks ASCII (huruf Latin dasar) sangat hemat, 1 byte per huruf.
- Kompatibel dengan ASCII: file ASCII otomatis juga valid UTF-8.
- Standar di web, file, dan jaringan.

## UTF-16

Karakter yang nomornya `U+0000` sampai `U+FFFF` memakai **satu** unit 16-bit (2 byte). Karakter di atas itu (emoji, dll.) memakai **dua** unit 16-bit (4 byte), disebut **surrogate pair**.

Nah, di sinilah blok `U+D800`–`U+DFFF` yang tadi kamu tanyakan dipakai. Unit 16-bit di rentang itu bukan karakter, melainkan "penanda" bahwa ia bagian dari pasangan:

```
😀 = U+1F600  →  dua unit 16-bit: 0xD83D 0xDE00
                                   ↑ surrogate depan  ↑ surrogate belakang
```

Karena angka-angka itu sudah "dipakai" sebagai penanda, Unicode **tidak boleh** memberinya karakter sungguhan. Itulah alasan `char` Rust menolaknya.

**Dipakai oleh:** Java (`String`), JavaScript, C#, dan Windows API.

## Perbandingan ukuran

```rust
fn main() {
    let teks = "Halo";
    println!("UTF-8 : {} byte", teks.len());                      // 4
    println!("UTF-16: {} byte", teks.encode_utf16().count() * 2); // 8

    let jepang = "日本語";
    println!("UTF-8 : {} byte", jepang.len());                      // 9
    println!("UTF-16: {} byte", jepang.encode_utf16().count() * 2); // 6
}
```

- Teks Latin: UTF-8 lebih hemat (4 vs 8 byte).
- Teks Jepang/Cina: UTF-16 bisa lebih hemat (6 vs 9 byte).

## Di Rust

- **`String` dan `&str` selalu UTF-8.** Inilah alasan `teks[0]` tidak diizinkan: indeks byte bisa jatuh di tengah karakter multi-byte.
- **`char` bukan UTF-8 maupun UTF-16**, melainkan nomor Unicode mentah (32 bit).
- Kalau perlu berinteraksi dengan UTF-16 (misalnya Windows API), pakai `encode_utf16()`.

## Ringkasan

| Aspek | UTF-8 | UTF-16 |
|---|---|---|
| Satuan dasar | 1 byte | 2 byte |
| Panjang per karakter | 1-4 byte | 2 atau 4 byte |
| Hemat untuk | Teks Latin/ASCII | Teks Asia (sebagian) |
| Kompatibel ASCII | Ya | Tidak |
| Dipakai di | Web, Linux, Rust, file umum | Java, JavaScript, C#, Windows |
| Surrogate | Tidak dipakai | Dipakai untuk karakter di atas `U+FFFF` |

Untuk saat ini, cukup ingat: **di Rust, teks selalu UTF-8**, dan `char` adalah nomor Unicode-nya.
