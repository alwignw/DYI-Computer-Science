Saat Anda membuat proyek baru di Rust menggunakan Cargo (dengan perintah `cargo new nama_proyek`), Cargo secara otomatis akan membuatkan struktur folder standar yang sangat rapi dan konsisten.

Berikut adalah anatomi atau struktur folder standar pada proyek Rust:

```text
nama_proyek/
├── .git/
├── .gitignore
├── Cargo.toml
├── Cargo.lock
└── src/
    └── main.rs

```

Mari kita bedah fungsi dari masing-masing file dan folder tersebut:

---

## 1. File Konfigurasi Utama

### `Cargo.toml`

Ini adalah file paling penting dalam proyek Rust. Formatnya adalah TOML (*Tom's Obvious, Minimal Language*). File ini bertindak sebagai **manifesto proyek** Anda (mirip seperti `package.json` di Node.js atau `pom.xml` di Maven).
Di sini Anda mengatur:

* **Metadata proyek:** Nama aplikasi, versi, edisi Rust yang digunakan, dan nama pembuat.
* **Dependencies:** Daftar pustaka pihak ketiga (*crates*) yang ingin Anda gunakan dari Crates.io.

### `Cargo.lock`

File ini dibuat otomatis oleh Cargo saat pertama kali Anda mengompilasi program. `Cargo.lock` mencatat versi pasti (*exact version*) dari semua pustaka yang diunduh. Jangan mengubah file ini secara manual. Fungsinya adalah memastikan bahwa siapa pun (atau server mana pun) yang mengompilasi kode Anda akan menggunakan versi pustaka yang sama persis, sehingga aplikasimu tidak rusak akibat pembaruan pustaka di masa depan.

### `.gitignore`

Jika Anda menggunakan Git, Cargo otomatis membuatkan file ini untuk memastikan file hasil kompilasi yang berukuran besar tidak ikut terunggah ke repositori Git Anda.

---

## 2. Folder Kode Sumber: `src/`

Semua kode pemrograman Rust wajib dimasukkan ke dalam folder `src/` (singkatan dari *source*).

* **`main.rs`:** Jika Anda membuat proyek aplikasi (*executable*), file ini adalah pintu masuk utama (*entry point*) dari program Anda. Kompiler Rust akan mencari fungsi `fn main()` di dalam file ini untuk pertama kali dijalankan.
* **`lib.rs` (Opsional):** Jika Anda membuat proyek berupa pustaka (*library*) yang tujuannya untuk dipakai oleh proyek lain (bukan aplikasi yang bisa langsung diklik/dijalankan), maka file utamanya dinamakan `lib.rs`, bukan `main.rs`.

---

## 3. Struktur Proyek yang Lebih Besar (Skala Produksi)

Seiring berkembangnya aplikasi Anda, struktur folder akan meluas untuk mengakomodasi pengujian, dokumentasi, dan pembagian modul kode agar tidak menumpuk di `main.rs`.

Berikut adalah standarisasi struktur folder Rust untuk skala besar:

```text
nama_proyek/
├── Cargo.toml
├── Cargo.lock
├── src/
│   ├── main.rs
│   ├── database.rs      <-- Modul terpisah
│   └── jaringan/        <-- Folder modul (sub-modul)
│       └── mod.rs
├── benches/             <-- Untuk uji performa (Benchmark)
│   └── benchmark_kecepatan.rs
├── examples/            <-- Contoh cara penggunaan kode Anda
│   └── contoh_fitur.rs
├── tests/               <-- Integration Tests (Uji integrasi sistem)
│   └── uji_aplikasi.rs
└── target/              <-- Folder hasil kompilasi (Otomatis muncul)
    └── debug/
        └── nama_proyek.exe

```

### Penjelasan Folder Tambahan:

* **`target/`:** Folder ini otomatis muncul setelah Anda menjalankan `cargo build`. Di sinilah hasil kompilasi berupa file biner (*executable*) dan file *cache* disimpan. Folder ini biasanya sangat besar, itu kenapa ia otomatis dimasukkan ke `.gitignore`.
* **`tests/`:** Folder khusus untuk menaruh kode pengujian integrasi (*integration testing*) untuk menguji apakah seluruh komponen aplikasi berjalan harmonis.
* **`benches/`:** Digunakan untuk menulis kode *benchmark* untuk mengukur seberapa cepat dan efisien fungsi yang Anda buat dalam hitungan nanodetik.
* **`examples/`:** Sangat berguna jika Anda membuat *library*, tempat menaruh contoh kode ringkas agar orang lain paham cara menggunakan *library* Anda.
