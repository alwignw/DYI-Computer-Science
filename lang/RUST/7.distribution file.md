Dalam konteks pemrograman Rust, istilah **"distribution file"** biasanya merujuk pada dua hal:

1. **File Biner Hasil Kompilasi:** Bagaimana Rust membungkus kode Anda menjadi file siap edar (*executable* atau *library*) yang akan dibagikan ke pengguna akhir.
2. **Rust Toolchain Distribution:** Bagaimana komponen internal Rust (seperti kompiler `rustc` dan *tool* `cargo`) didistribusikan ke komputer Anda saat instalasi.

Mari kita bahas poin pertama yang paling sering dihadapi oleh pengembang, yaitu bagaimana Rust menghasilkan file aplikasi yang siap didistribusikan.

---

## 1. Karakteristik File Distribusi Rust (Biner Mandiri)

Salah satu kekuatan terbesar Rust dalam hal distribusi adalah kemampuannya menghasilkan file biner murni yang **bersifat mandiri (*standalone executable*)**.

Saat Anda menjalankan perintah:

```bash
cargo build --release

```

Cargo akan menghasilkan file distribusi di dalam folder `target/release/[nama_proyek]` (atau `.exe` di Windows).

Berikut adalah karakteristik utama dari file distribusi tersebut:

### A. Tautan Statis (*Statically Linked*) secara Default

Secara default, Rust menggunakan *static linking*. Artinya, semua kode Anda, ditambah semua pustaka pihak ketiga (*dependencies* yang ada di `Cargo.toml`), serta pustaka standar Rust (*Rust Standard Library*), **digabungkan menjadi satu file tunggal**.

* **Keuntungan:** Pengguna akhir tidak perlu menginstal apa pun di komputer mereka (tidak butuh Java runtime, tidak butuh Python interpreter, tidak butuh .NET framework). Mereka cukup mengklik atau menjalankan satu file biner tersebut, dan aplikasi langsung berjalan.
* **Konsekuensi:** Ukuran file biner Rust cenderung lebih besar di awal (bisa beberapa Megabyte untuk aplikasi sederhana) karena semua dependencies sudah dibungkus di dalamnya.

### B. Ketergantungan pada *C Runtime* (glibc vs musl)

Meskipun pustaka Rust ditautkan secara statis, secara default di sistem operasi Linux, Rust masih bergantung secara dinamis pada *C Runtime Library* (`glibc`) bawaan OS untuk berkomunikasi dengan Kernel.

Jika Anda ingin membuat file distribusi yang **100% total mandiri** (bisa berjalan di distro Linux mana pun, bahkan di dalam *container* Docker yang sangat kosong seperti Alpine Linux), Anda bisa mengubah target distribusinya menggunakan **`musl`**:

```bash
# Menambahkan target musl
rustup target add x86_64-unknown-linux-musl

# Kompilasi untuk distribusi yang benar-benar independen
cargo build --release --target x86_64-unknown-linux-musl

```

## 2. Jenis-Jenis File Hasil Distribusi Rust

Tergantung pada jenis proyek yang Anda atur di `Cargo.toml`, Rust dapat mendistribusikan kode Anda ke dalam beberapa format file:

| Format File | Ekstensi (Windows / Linux) | Kegunaan |
| --- | --- | --- |
| **Executable (Biner Utama)** | `.exe` / *tanpa ekstensi* | Aplikasi siap pakai untuk pengguna akhir (CLI, server backend, game). |
| **rlib (Rust Library)** | `.rlib` | Format internal Rust. Digunakan jika Anda ingin mendistribusikan kode agar bisa dipakai oleh proyek Rust lainnya. |
| **cdylib (C Dynamic Library)** | `.dll` / `.so` | Pustaka dinamis yang bisa dipanggil oleh bahasa pemrograman lain (seperti Python, C++, atau Node.js). |
| **staticlib (Static Library)** | `.lib` / `.a` | Pustaka statis yang bisa dikompilasi bersama dengan aplikasi berbasis C/C++. |

## 3. Strategi Optimasi Ukuran File Distribusi

Karena Rust memasukkan semua hal ke dalam satu file biner, terkadang ukuran file distribusinya bisa agak besar. Komunitas Rust memiliki trik khusus di dalam `Cargo.toml` untuk melakukan rekonstruksi dan memperkecil ukuran file distribusi (*binary stripping* dan optimasi agresif).

Anda bisa menambahkan konfigurasi ini di `Cargo.toml` untuk distribusi produksi:

```toml
[profile.release]
opt-level = 'z'     # Mengoptimalkan ukuran file (mengecilkan biner)
lto = true          # Link-Time Optimization, menghapus kode mati di seluruh dependencies
codegen-units = 1   # Mengurangi paralelisasi saat kompilasi demi optimasi yang lebih baik
strip = true        # Menghapus informasi debug dan simbol-simbol yang tidak diperlukan

```

Dengan menambahkan konfigurasi di atas, ukuran file distribusi Rust Anda bisa menyusut hingga **50% sampai 80% lebih kecil** dari ukuran standar.

## 4. Mengenal Distribution File pada Perangkat Sistem (Rustup Components)

Jika yang Anda maksud adalah file distribusi saat menginstal Rust itu sendiri, Rust menggunakan sistem komponen modular yang dikelola oleh `rustup`. Saat Anda menginstal Rust, Anda mengunduh paket distribusi resmi yang berisi:

* `rustc` (Kompiler)
* `rust-std` (Pustaka standar untuk arsitektur komputer Anda)
* `cargo` (Manajer paket)
* `rust-docs` (Dokumentasi luring)

Anda bahkan bisa mengunduh *distribution file* untuk arsitektur lain (misal Anda menggunakan Mac M1/M2/M3 tetapi ingin mendistribusikan aplikasi untuk Windows x64). Proses ini disebut **Cross-Compilation**.

Apakah Anda sedang bersiap untuk mendistribusikan aplikasi Rust Anda ke sistem operasi yang berbeda (Cross-Compiling), atau ingin fokus mengoptimalkan ukuran file biner aplikasi Anda saat ini?
