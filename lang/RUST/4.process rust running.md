Proses bagaimana program Rust berjalan—mulai dari kode teks yang Anda tulis hingga menjadi instruksi yang dieksekusi oleh prosesor—sangat menarik. Karena Rust tidak menggunakan *Garbage Collector* atau *Virtual Machine* (seperti Java atau Python), prosesnya berfokus penuh pada **keamanan di awal** dan **kecepatan di akhir**.

Secara garis besar, proses ini dibagi menjadi dua fase utama: **Fase Kompilasi (Waktu Desain)** dan **Fase Eksekusi (Waktu Jalan)**.

---

## 1. Fase Kompilasi (*Compile-Time*)

Ketika Anda mengetik perintah `cargo build` atau `cargo run`, Rust tidak langsung menjalankan kode Anda. Kompiler Rust (`rustc`) akan membedah kode Anda melalui beberapa tahapan yang sangat ketat:

### A. Analisis Sintaks & Tipe Data (*Parsing & Type Checking*)

Kompiler membaca file `.rs` Anda, memeriksa apakah ada salah ketik (sintaks), dan memastikan semua tipe data sudah benar dan cocok.

### B. Pemeriksaan Sistem Kepemilikan (*The Borrow Checker*)

Ini adalah tahap paling krusial dan unik di Rust. Kompiler akan menganalisis kode Anda untuk memastikan aturan **Ownership** (Kepemilikan) dan **Borrowing** (Peminjaman) dipatuhi.

* Kompiler memeriksa: *Apakah ada variabel yang digunakan setelah datanya dihapus? Apakah ada dua proses yang mencoba mengubah data yang sama secara bersamaan?*
* Jika ada potensi masalah memori, kompilasi langsung **gagal** di sini dan menampilkan pesan *error*.

### C. Analisis Kode Menengah (*MIR - Mid-level Intermediate Representation*)

Setelah lolos dari *Borrow Checker*, Rust mengubah kode Anda menjadi representasi tingkat menengah (MIR). Di tahap ini, Rust melakukan optimasi internal agar kode menjadi lebih efisien.

### D. Generator Kode LLVM (*Backend*)

Rust tidak membuat bahasa mesinnya sendiri dari nol. Ia menyerahkan MIR tadi ke **LLVM** (teknologi kompilator modern yang juga digunakan oleh C++ Clang dan Swift). LLVM bertugas mengoptimalkan kode secara agresif untuk arsitektur prosesor spesifik Anda (X86, ARM, dll) dan mengubahnya menjadi file biner/eksekusi (misalnya file `.exe` di Windows atau biner ELF di Linux).

---

## 2. Fase Eksekusi (*Runtime*)

Setelah kompilasi selesai, Anda mendapatkan sebuah file biner mandiri (*standalone executable*). Ketika Anda menjalankan file tersebut, inilah yang terjadi di dalam komputer:

### A. Alokasi Memori yang Terprediksi

Saat program berjalan, ia menggunakan memori komputer dengan dua cara yang sangat efisien:

* **Stack:** Digunakan untuk menyimpan data yang ukurannya sudah pasti saat kompilasi (misal: angka, boolean). Alokasi dan penghapusan di Stack sangat cepat karena polanya terstruktur (LIFO - *Last In, First Out*).
* **Heap:** Digunakan untuk data yang ukurannya bisa berubah-ubah saat program berjalan (misal: teks panjang dari input *user*, daftar data dinamis).

### B. Manajemen Memori Tanpa Jeda (*RAII*)

Ini rahasia kenapa Rust bisa secepat C++ tanpa *Garbage Collector*. Rust menggunakan prinsip bernama **RAII (Resource Acquisition Is Initialization)**.

* Ketika sebuah fungsi berjalan dan membuat variabel di Heap, variabel tersebut memiliki "Pemilik" (*Owner*).
* Begitu fungsi selesai berjalan, variabel tersebut keluar dari ruang lingkup (*out of scope*).
* Di titik inilah Rust **langsung menyisipkan instruksi pembersihan memori secara otomatis** tepat saat kompilasi. Jadi saat program berjalan, memori langsung dibebaskan saat itu juga tanpa ada sistem *Garbage Collector* yang perlu memindai memori di latar belakang.

### C. Eksekusi Langsung di CPU

Karena sudah berbentuk bahasa mesin murni, instruksi program Rust langsung dikirim dan dieksekusi oleh prosesor tanpa perantara. Tidak ada *interpreter* yang menerjemahkan kode baris demi baris saat berjalan, dan tidak ada jeda acak untuk membersihkan sampah memori. Program berjalan dengan kecepatan penuh dan penggunaan memori yang stabil (datar).

---

## Ringkasan Perbandingan

| Proses | Bahasa dengan GC (e.g., Java, Go) | Bahasa Rust |
| --- | --- | --- |
| **Saat Kompilasi** | Cepat, pemeriksaan memori longgar. | Lebih lama, pemeriksaan memori sangat ketat (*Borrow Checker*). |
| **Ukuran File** | Membawa *runtime* / VM yang cukup besar. | Sangat ringkas karena hanya berisi kode mesin murni. |
| **Saat Berjalan** | Ada jeda (*pause*) berkala karena GC membersihkan memori. | Stabil, cepat, memori langsung dihapus saat tidak dipakai. |

> **Analogi sederhana:** Bahasa lain membiarkan Anda membangun rumah dengan cepat, tetapi Anda harus menyewa petugas kebersihan (*Garbage Collector*) untuk membereskan sampah saat Anda tinggal di dalamnya. Rust memaksa Anda bekerja keras membersihkan sisa bahan bangunan *selama proses konstruksi*, sehingga saat rumah jadi, rumah itu langsung bersih dan siap ditempati dengan efisien.
