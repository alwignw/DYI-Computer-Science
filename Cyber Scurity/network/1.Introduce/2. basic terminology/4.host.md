Berikut adalah analisis **5W+1H** mengenai konsep **Host** dalam konteks teknologi informasi, jaringan, dan komputasi:

---

### 1. What (Apa itu Host?)

Dalam dunia jaringan komputer, **Host** (Inang) adalah **setiap perangkat keras yang terhubung ke dalam suatu jaringan dan memiliki alamat IP (*IP Address*) unik**.

Host adalah entitas yang dapat mengirim, menerima, atau meneruskan data melalui jaringan. Penting untuk dicatat bahwa dalam model *Client-Server*, baik perangkat *client* maupun *server* adalah sebuah Host. Namun, tidak semua perangkat jaringan disebut Host; perangkat interkoneksi murni seperti *switch* bodoh (*unmanaged switch*) atau *hub* yang tidak memiliki IP *address* tersendiri untuk manajemen data tidak dikategorikan sebagai Host.

Selain dalam konteks jaringan, kata "Host" juga digunakan dalam beberapa istilah spesifik:

* **Web Hosting / Cloud Host:** Komputer server tempat menyimpan berkas-berkas *website* agar bisa diakses internet.
* **Virtualization Host:** Sebuah server fisik yang menjalankan *software* hypervisor untuk menampung beberapa sistem operasi virtual (*Virtual Machines* / VM).

---

### 2. Who (Siapa atau Apa saja yang dikategorikan sebagai Host?)

Secara teknis, "Who" di sini merujuk pada segala jenis *node* aktif di dalam jaringan:

* **Komputer Pengguna:** Laptop, PC Desktop, MacBook.
* **Gadget & IoT:** Smartphone, tablet, jam tangan pintar, hingga kamera CCTV pintar yang terhubung ke Wi-Fi rumah.
* **Infrastruktur Jaringan Pintar:** Server, printer jaringan, *network-attached storage* (NAS), serta *router* atau *switch layer 3* yang memiliki IP manajemen.

---

### 3. Where (Di mana posisi Host berada?)

Host berada di **setiap titik ujung jaringan (endpoints)** atau di dalam topologi jaringan terdistribusi.

Di internet, posisi sebuah Host diidentifikasi secara logis melalui **IP Address** miliknya dan secara fisik melalui kartu jaringan (*Network Interface Card* / NIC) yang memiliki **MAC Address**. Agar lebih mudah diingat oleh manusia, alamat logis Host ini sering kali dipetakan ke dalam nama domain menggunakan sistem DNS (Domain Name System). Contohnya, Host dengan nama `www.google.com` merujuk pada IP server milik Google.

---

### 4. When (Kapan sebuah perangkat mulai disebut sebagai Host?)

Sebuah perangkat resmi bertindak sebagai Host **segera setelah ia terhubung ke jaringan dan mendapatkan alokasi IP Address**, baik secara dinamis melalui protokol DHCP (*Dynamic Host Configuration Protocol*) maupun secara manual melalui konfigurasi IP statis.

Dalam operasional harian, status Host ini aktif selama perangkat tersebut menyala dan antarmuka jaringannya (*network interface*) mampu melakukan jabat tangan jaringan (*network handshake*) untuk bertukar paket data.

---

### 5. Why (Mengapa konsep Host ini penting dalam arsitektur TI?)

Konsep Host diperlukan untuk mendefinisikan batas, identitas, dan tanggung jawab dalam komunikasi data:

* **Identifikasi Unik:** Tanpa adanya identitas Host (IP Address), paket data yang dikirimkan di internet tidak akan pernah tahu ke mana harus pergi dan dari mana ia berasal.
* **Manajemen Sumber Daya:** Dalam arsitektur *cloud* atau virtualisasi, konsep *Host vs Guest* digunakan untuk memisahkan penyedia sumber daya fisik (Host) dengan sistem operasi pengguna yang menumpang di atasnya (Guest).
* **Keamanan Jaringan:** Memudahkan tim keamanan TI untuk melacak aktivitas mencurigakan berdasarkan perilaku *Host* tertentu (misalnya mendeteksi *Host* mana yang terinfeksi malware di dalam kantor).

---

### 6. How (Bagaimana Host berkomunikasi satu sama lain?)

Komunikasi antar-Host terjadi melalui standarisasi lapisan protokol, seperti model **TCP/IP** atau **OSI Layer**:

1. **Pengalamatan (Addressing):** Host A ingin mengirim data ke Host B. Host A harus mengetahui alamat IP tujuan Host B (bisa dicari melalui DNS jika menggunakan nama domain).
2. **Enkapsulasi (Encapsulation):** Data dari aplikasi di Host A dibungkus menjadi paket-paket kecil, diberi label IP asal dan IP tujuan, serta port aplikasi yang dituju.
3. **Pengiriman (Routing):** Paket dikirim keluar dari Host A melalui *gateway* lokal, melewati berbagai *router* di internet, hingga sampai ke jaringan Host B.
4. **Dekapsulasi & Respons (Decapsulation):** Host B menerima paket tersebut, membongkar bungkus protokolnya, memeriksa apakah IP tujuannya sudah cocok dengan dirinya, lalu meneruskan data mentah ke aplikasi yang tepat untuk diproses.
